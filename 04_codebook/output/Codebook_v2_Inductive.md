## Coding Instructions (carried forward from v1)

**Unit of analysis:** Sentence or clause. Extend to the full paragraph only if meaning cannot be extracted from a shorter unit.

**Multiple codes per passage:** A passage may receive codes from different sections simultaneously (e.g., a sentence can be both `REG_TRL` and `COG_LINEAR`). Always code exhaustively for a given passage.

**Programme tag:** Mark each coded passage `[PATH]` (Pathfinder), `[STEP]` (STEP Scale Up), or `[SHARED]`.

**Ambiguity flag:** In Pass 2, `[?]` flags inherited from Pass 1 are systematically resolved. New `[?]` flags should be avoided at this stage; any residual ambiguity should be documented as a coding rule refinement in Section 9.

**Surface-visibility standard (clarified in Pass 2):** `LOGIC_TENSION` and similar relational codes apply only where the tension is legible in the text itself. Constructed-argument tensions are treated as analytical observations (Pattern A — tension-dissolution), not as `LOGIC_TENSION` codings. See Section 7, Pattern A.

### Key distinctions retained from v1 (Logics codebook)

- **Science vs. Profession** — Science logic valorises the *content* of knowledge (novelty, discovery). Professional logic valorises *certified process* (due diligence, standardised tools, credentialled evaluators).
- **Market vs. State** — Both can justify the same instrument (equity investment) from opposite directions. Market logic justifies equity as efficient capital allocation; state logic justifies equity as a vehicle for control and condition-setting (IP retention, strategic safeguards). Check *what the equity instrument is asked to achieve*.
- **State vs. Profession** — State logic derives authority from democratic mandate and legislative process. Professional logic derives authority from expertise and credentialling.

### Pattern A — Tension-Dissolution _(confirmed in Pass 2)_

**Description (from Readthrough_Notes_v1.md):** Logics are presented as naturally complementary, and the text explicitly dissolves the tension between them by treating them as equivalent or mutually reinforcing — without acknowledging that they can and do conflict in practice.

**Distinction from `LOGIC_TENSION`:** `LOGIC_TENSION` requires conflict to be surface-visible. Pattern A passages present logics as complementary; the tension is structurally present but rhetorically suppressed.

**Instances at start of Pass 2:** [005], [006]/[007], [010], [019], [039], [057], [061], [082]; extended in Pass 2 to [102] (entry self-identifies as Pattern A); intersects with [056] (Excellence criterion folds market vocabulary into science quality criteria without acknowledging conflict). **Group A extension (Pass 2):** [044] (Gatekeepers — cross-bullet tension between produces-vs-works framings, dissolved by complementary presentation) and [109] (Specific Objectives Area 1 — co-equal listing of science proof-of-concept and market exploitation deliverables, with the structural tension surfacing only across [108]→[109]).

**Group B extension (Pass 2):** [003] (Strategic Goal 5 — SCIENCE↔MARKET and MARKET↔STATE tensions constructed via interpretive moves "quietly reframing what counts as valuable science"; `LOGIC_TENSION` withdrawn at v2-021) and [008] (Overview "Open" / Challenges / STEP paragraph — SCIENCE↔STATE tension constructed via continuous-arc paragraph architecture from "any field" → "strategic interest" → "named technology domains"; `LOGIC_TENSION` withdrawn at v2-023). Both confirm the Pattern A signature at the introductory Strategic Goals / Overview level.

**Pass 2 resolution:** **Option (b) + (c) combined — coding rule already in force; analytical observation confirmed.**

- **Option considered:** (a) promote to new code; (b) refine via coding rule; (c) retain as analytical observation.
- **Decision:** (b) coding-rule refinement **already in place** as Section 9 rule 1 (surface-visibility standard for `LOGIC_TENSION`) — introduced at the start of Pass 2 specifically to operationalise the Pattern A / `LOGIC_TENSION` distinction. **No new rule required.** (c) Pattern A retained as the analytical-observation counterpart to rule 1.
- **Rationale:** Pattern A is the inverse of `LOGIC_TENSION`. Where `LOGIC_TENSION` marks surface-visible conflict, Pattern A marks surface-suppressed complementarity that masks structural conflict. Rule 1 already routes constructed-argument tensions into Pattern A. Promoting Pattern A to a code would either double-count (every Pattern A passage would also need a positive `PATTERN_A` code on top of the substantive logic codes) or compete with rule 1 (creating ambiguity about when to apply which). Keeping it as an analytical observation is the cleaner architecture.
- **Pass 2 recoding:** [019] re-coded — `LOGIC_TENSION` withdrawn (constructed-argument, market/state framings presented as equivalent). [056], [057], [102] coding unchanged — Pass 1 had already correctly applied the conservative threshold; Pattern A now formally captures the analytical observation.
- **Frozen-notes consequence:** [001] addendum (line 201 of `Readthrough_Notes_v1.md`) self-flags its `LOGIC_TENSION` coding as constructed-argument — the same error pattern as [019]. ### Candidate Patterns Tested and Not Confirmed _(Pass 2)_

This sub-section records candidate patterns examined during Pass 2 that did not meet the threshold for formalisation as patterns. The negative findings themselves carry analytical value — they sharpen the boundaries of the confirmed patterns and identify configurations where the institutional architecture *could* have been templated but was not.

#### Candidate Pattern F — Sustainability as State Template _(not confirmed)_

**Hypothesis:** Sustainability framing recurs across Challenge chapters as a standardised state legitimation insert, analogous to Pattern C (State Social Equity Template). If confirmed, every Challenge would carry sustainability language regardless of subject matter, indicating a Pattern C-equivalent universal template embedded in the institutional architecture.

**Source:** [096] flag (II.2.1 Background and Scope — energy and environmental consequence) raised the question; [099], [125], [129] provided cross-Challenge test data.

**Result:** **Not confirmed.** The universality test fails at II.2.2 (Biotechnology for Healthy Ageing): "No sustainability or environmental language present. First data point for the hypothesis that sustainability only enters Challenge chapters through Commission Communications specific to the Challenge topic, not as a universal insert" (`Readthrough_Notes_v1.md` line 1689). Sustainability is **subject-matter-dependent**, not a universal template.

**Substantive finding (preserved as analytical observation):** When sustainability does appear, it enters via at least four distinct mechanisms:

1. **Commission Communication policy-citation** — the Challenge cites a Commission Communication that itself carries the sustainability frame; the frame flows through by institutional inheritance ([099] — "Advanced Materials for Industrial Leadership... addressing sustainability, circularity and safety issues").
2. **Explicit environmental-consequence framing** — sustainability appears as descriptive context establishing the problem the Challenge addresses ([096] — IoT energy consumption, battery waste).
3. **Sector-definition** — sustainability is constitutive of the technology field itself (around [117]–[120], clean and resource-efficient technologies as a STEP critical-area category).
4. **Technical efficiency-proxy** — sustainability is absorbed into methodology requirements via constrained-resource specifications, without explicit environmental framing or policy citation ([125]/[129] — DeepRAP compute-constraint requirement as proxy sustainability).

**Analytical value as contrast with Pattern C:** Pattern C (State Social Equity Template — gender mainstreaming, DEI) operates as a *universal* insert reproduced in near-identical wording across instruments and Challenges regardless of subject matter. Sustainability operates as an *adaptive* state-policy entry vector that adapts its expression to Challenge content. The contrast sharpens what Pattern C actually templates: the institutional architecture carries a small set of state priorities universally (gender mainstreaming) while letting other state priorities (sustainability) enter through subject-matter-appropriate channels. This distinction is itself a finding about how the state distributes its priorities across the institutional architecture — universal templating reserved for cross-cutting normative commitments (equity), adaptive templating for substantive policy content (environment, security, sovereignty).

**Pass 2 resolution:** **No new code, no new rule, no codebook-level change.** All four mechanisms are already captured by existing codes — `LOGIC_STATE` carries the policy substance whenever it organises a passage; rule 7 (vocabulary-vs-organising) governs the threshold for whether sustainability vocabulary rises to coding. The finding lives entirely at the analytical level. Feeds Ch 4 (description of the four mechanisms) and Ch 5 (the universal-vs-adaptive contrast as a meso-level finding about state-priority distribution).

Code `ISO_COERCIVE` where (a) the authority asserted carries explicit sanction force (termination, suspension, mandated amendment) and (b) the source of obligation is the grant agreement or a Programme Manager acting under it. Co-code `LOGIC_STATE` where the state is named as the actor wielding the contractual power (e.g., "the Agency may suspend or terminate"). Soft-direction language without sanction force ("may be requested to join", "encouraged to collaborate") remains below threshold and is carried as Pattern B observation only. None: [059] (tiebreaker ranking), [067] (geographic context for consortium structure), [071] (budget allocation amount).
7. _Vocabulary-vs-organising standard for logic coding in procedural / administrative passages._ A logic is coded only where it *organises* the passage — i.e., where its principles, evaluative criteria, or institutional authority actively shape what the passage requires or prescribes. Vocabulary-level signals embedded in procedural, administrative, or budgetary passages do not in themselves warrant primary coding. Below-threshold categories include: **(a)** VC vocabulary attached to administrative actions ("follow on investments", "accelerate", "Booster", "Fast Track" — [014] precedent); **(b)** state-as-administrative-funder language without strategic rationale ("direct financial support", "budget is set aside" — [012] precedent); **(c)** management-register language without invoked credentialled authority ("proactive management" without expert/peer/standards anchor); **(d)** normative-identity language describing applicant ideal types ("visionary researchers and innovators") rather than science-organising governance (peer review, researcher-led agenda, scientific merit as decisive criterion). Where the passage's *subject* is procedure / budget / labels / ideal-type identity and a logic appears only via vocabulary register, code None for that logic. Apply alongside rule 1 (surface-visibility for `LOGIC_TENSION`) and rule 6 (structural state inference). Distinguish from above-threshold cases where the vocabulary names the *organising principle* of the instrument (e.g., "user uptake" at [011] names demand-side market validation as the rationale, not a vocabulary register on an administrative action).
